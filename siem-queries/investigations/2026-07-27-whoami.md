# Investigation: whoami

## Summary of findings

Hunt for `whoami` execution in BOTS v3 Sysmon process-creation events (EventID 1).
Returned **2 aggregated rows** covering **6 whoami executions**, all on a single host,
**`FYODOR-L.froth.ly`**, and every one spawned by **`powershell.exe`**:

- **`AzureAD\FyodorMalteskesko`** — 5 executions: plain `whoami` and `whoami /groups`.
  Enumerating your own identity and group memberships is textbook **discovery**,
  typically run early in post-compromise reconnaissance.
- **`NT AUTHORITY\SYSTEM`** — 1 execution of `whoami`, also from `powershell.exe`.
  Discovery running in a **SYSTEM (elevated) context** launched from PowerShell is the
  more suspicious signal here: it suggests activity in a privileged process rather than
  a normal interactive user checking their own account.

The common thread — discovery commands parented by PowerShell, including one in SYSTEM
context — is consistent with hands-on-keyboard or scripted reconnaissance on this host.
`FYODOR-L.froth.ly` is worth pivoting on for surrounding PowerShell activity, network
connections (Sysmon EventID 3), and any credential-access or execution around the same
timeframe.

## ATT&CK techniques

- [[T1033]] — System Owner/User Discovery (`whoami`)
- [[T1069]] — Permission Groups Discovery (`whoami /groups`)

## Query

Result count: **2** (rows; 6 underlying whoami executions)

```spl
index=botsv3 sourcetype="xmlwineventlog:microsoft-windows-sysmon/operational" "<EventID>1</EventID>" whoami
| rex "Name=.Image.>(?<Image>[^<]+)"
| rex "Name=.CommandLine.>(?<CommandLine>[^<]+)"
| rex "Name=.User.>(?<User>[^<]+)"
| rex "Name=.ParentImage.>(?<ParentImage>[^<]+)"
| rex "<Computer>(?<Computer>[^<]+)"
| search Image="*whoami.exe"
| stats count values(CommandLine) as command_lines values(ParentImage) as parent_process by Computer User
| sort - count
```

Timerange: `-15y` -> `now` (BOTS v3 data is from August 2018).
